# RustWTM 0.38.2 release scope and validation

## Scope

One fix to turning on *Always open RustWTM as administrator*. Protocol 20
is unchanged; a 0.38.1 service and a 0.38.2 window work together.

- **Administrator tasks on a slow machine.** RustWTM registers, removes
  and starts its administrator tasks through Windows PowerShell and
  stopped waiting after 15 seconds. On a freshly started machine, with
  the ScheduledTasks module loading for the first time, PowerShell took
  longer: CI's upgrade jobs failed with "Windows Task Scheduler request
  timed out", killed at exactly 15 seconds in 8 of 21 jobs. Measured on
  the CI runners, the first run took 10.4 to 27.2 seconds. PowerShell now
  gets 60 seconds.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the workspace tests pass on the
developer host from a clean checkout (1247 passed, 23 ignored).
`scripts/ci/verify-release.ps1 -Tag v0.38.2` checks the published
assets. CI adds 0.38.1 as an upgrade baseline, with the SHA-256 of its
published MSI; the upgrade jobs turn on the administrator tasks.

Test changes since 0.38.1:

- `wtm-gui`: page reloads follow a clock a test can freeze. On a slow CI
  runner a page's reload timer could fire between finding a row and
  clicking it, and a click test missed its row.

Not covered: a machine where Windows PowerShell needs more than 60
seconds; the window then reports the time-out as before.
