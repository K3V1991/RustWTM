# RustWTM 0.39.1 release scope and validation

## Scope

One fix to closing the window to the tray
([#5](https://github.com/RustWTM/RustWTM/issues/5)). Protocol 20 is
unchanged; a 0.39.0 service and a 0.39.1 window work together.

- **Close button after a second start.** Starting RustWTM while it runs
  in the tray brings back the existing window. That start shows the
  window through Win32 alone, which the window library (winit) does not
  notice: it still counted the window as hidden and skipped the close
  button's hide request as no change, so the button did nothing. Closing
  to the tray, and hiding on start, now also hide the window natively.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the workspace tests pass on the
developer host from a clean checkout (1275 passed, 23 ignored).
`scripts/ci/verify-release.ps1 -Tag v0.39.1` checks the published
assets. CI adds 0.39.0 as an upgrade baseline, with the SHA-256 of its
published MSI.

The fault was reproduced with a probe that started RustWTM a second
time and pressed the close button: the window stayed visible before the
fix and was hidden after it.

Test changes since 0.39.0:

- `wtm-gui`: hiding the window to the tray also hides the native window
  that another start showed (`hiding_also_hides_the_native_window_another_start_showed`).

Not covered: other ways of showing the window outside winit, such as a
third-party tool calling `ShowWindow`; the close button handles them the
same way, but no test drives them.
