# RustWTM 0.39.0 release scope and validation

## Scope

Safer fan control, service data in the window that follows the
connection, and restores that are kept until they succeed. Protocol 20 is
unchanged; a 0.38.2 service and a 0.39.0 window work together.

- **Fan control.** Switching the service to monitoring revokes software
  fan control at once (a revision the worker checks before and after
  each write) and asks for hardware defaults; a profile is applied again
  after switching back. A failed reading publishes only the failure, so
  stale readings and cooling state are not shown as current. A missing
  or no longer eligible channel goes back to hardware automatic. A
  retired helper worker cannot overwrite the new worker's readings. The
  helper is started again when a reading comes back without a report.
  In the C# helper each lease follows the control instance it was given
  for; a replacement control is driven only after the previous one is
  restored, and on exit failed restores are retried once and reported
  through the exit status.
- **Service data follows the connection.** The window counts accepted
  connections. On a lost connection it switches to local mode and drops
  the configuration, kill list, Telegram settings and recorded history it
  had read; incident replay and the file locks page drop late results.
  A Telegram save or test carries the connection it was made for and is
  refused or discarded when another service answers.
- **Protocol mismatch.** `wtm_ipc::ProtocolMismatch` carries both
  versions, so `wtm` and the window name the side to update.
- **Restores kept until they succeed.** App power keeps a plan restore
  pending while the active plan cannot be read, keeps the previous
  request when a switch fails, and serves a new request after the user
  chose a plan. Core placement keeps a failed restore for the next pass
  and the last placement that worked when an update fails.
- **Smaller fixes.** Exact size parsing in `wtm`; a system query bounded
  by its remaining time; `install.ps1` stops when it cannot remove the
  old directory, and `uninstall.ps1` removes the service's executable and
  itself last so a failed removal can be run again.

The work was written in another session and taken over uncommitted after
it had been idle for hours; it was reviewed, completed (a missing
translation and the changelog) and committed in eight pieces, each of
which builds on its own.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the workspace tests pass on the
developer host from a clean checkout (1274 passed, 23 ignored). The hardware helper's
self-test, `scripts/ci/test-install-lifecycle.ps1` and
`scripts/ci/test-uninstall-lifecycle.ps1` pass.
`scripts/ci/verify-release.ps1 -Tag v0.39.0` checks the published
assets. CI adds 0.38.2 as an upgrade baseline, with the SHA-256 of its
published MSI.

New tests (27 in Rust, plus the helper self-test and the script tests):

- `wtm-service` hardware: monitoring revokes the previous permission and
  wakes the worker; cooling requires a current temperature and an
  eligible channel; a retired worker cannot replace current readings or
  control state.
- `wtm-core` hardware: a collection error publishes only the failure; a
  missing sample report schedules a reconnection; shutdown retries a
  failed restore within the remaining budget, and stops after success,
  two failures or an expired budget.
- C# helper self-test: leases follow the control instance, a failed
  restore of the previous control refuses the replacement, and exit
  retries only failed restores.
- `wtm-gui`: a reconnect scopes cached settings and saves to the current
  service; a disconnect drops recorded history; a late Telegram reply
  keeps the connection message; an old Telegram test is not sent to a
  replacement service; recorded history reloads for a replacement
  service; the Telegram form reloads and drops its draft on reconnect,
  sends its session and shows the right recovery for each connection
  problem; late replay and file lock results are dropped.
- `wtm-cli`: both protocol mismatches point to the right recovery, core
  placement shows the local topology on a mismatch, and sizes parse
  without rounding or saturating.
- `wtm-service`: App power defers a restore while the active plan is
  unknown, keeps the previous request until a switch succeeds and serves
  a new request after an override; core placement keeps a failed
  restore, waits for a release before switching methods and keeps the
  last successful placement after a failed update.
- `wtm-core`: a system query rejects a reply after its budget.
- Install and uninstall scripts: a failed removal of the old directory
  stops the installer, and an uninstall that failed half way completes
  on a second run.

Not covered: a real fan controller whose control instance changes while
the helper runs, and a live service restart while the window is open.
