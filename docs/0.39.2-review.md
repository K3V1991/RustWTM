# RustWTM 0.39.2 release scope and validation

## Scope

One fix to closing the window to the tray. Protocol 20 is unchanged; a
0.39.1 service and a 0.39.2 window work together.

- **Closing a minimized window.** Closing RustWTM while it is minimized,
  for example from the taskbar, quit it instead of keeping it in the
  tray. eframe does not draw a minimized window: it delivers the close
  request in a pass that runs only `App::logic`, and RustWTM looked for
  the request in `App::ui`. The request is now handled in `App::logic`,
  which runs in every pass. Exit from the tray menu and the restart
  after an update still quit: they mark the exit before they close the
  window.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the workspace tests pass on the
developer host from a clean checkout (1277 passed, 23 ignored). Two
tests that start processes failed while other builds loaded the host:
a killed `ping` still ran after 300 ms, and antivirus held a copied
executable for over 10 seconds. Both passed when run again.
`scripts/ci/verify-release.ps1 -Tag v0.39.2` checks the published
assets. CI adds 0.39.1 as an upgrade baseline, with the SHA-256 of its
published MSI.

A probe built on eframe 0.37 with the Glow renderer, as RustWTM uses,
minimized its window and sent it `WM_CLOSE`: with the request handled in
`App::ui` the probe quit, with it handled in `App::logic` the window
was hidden and the probe kept running.

Test changes since 0.39.1:

- `wtm-gui`: a close request in a pass that draws nothing hides the
  window to the tray (`closing_a_minimized_window_keeps_rustwtm_in_the_tray`),
  and still quits when there is no tray icon
  (`closing_without_a_tray_icon_still_quits`). The first fails with the
  check moved back out of `App::logic`.

Not covered: the real RustWTM window closed from the taskbar; the probe
and the tests stand in for it.
